# WP-02 evidence and handoff — Catalogue, Publisher, and Validator

**Status:** Implemented and locally verified; strengthened by C-W1-02/C-W1-04 after independent Wave 1 audit. No database, gateway, live-template, deployment, or external-system change was made.

## Delivered capability

`packages/automation-catalog/src/catalog.mjs` is the deterministic GAP v0.1 validation and index implementation. It uses pinned `ajv` 8.20.0 with `ajv-formats` 3.0.1 and executes the seven WP-01 Draft 2020-12 schemas.

The validator checks:

- package manifest shape, lifecycle, SemVer, only-`n8n` v0.1 runtime, and required references;
- referenced input/output/configuration JSON Schema documents;
- evaluation suite, fixtures, monitoring, maintenance, deployment, and provenance documents;
- safe package-relative paths;
- n8n workflow parsing, unique node IDs/names, valid connection targets, declared trigger presence, and `n8n-core-only-v0.1` node policy;
- credential objects and secret/private-key/connection-string/bearer/AWS-key-shaped content without echoing the matched value;
- commercial-use clearance and provenance review;
- exact workflow and WP-01 canonical package digest;
- all `certified` release claims are rejected until WP-06 supplies a verifiable independent-receipt implementation;
- unique automation ID + version in the source catalogue.

The generated `automations/catalog/index.json` is an operator metadata read model: it never includes a workflow body, secret declaration/value, or mutable runtime state. `--check` compares its complete bytes to a freshly generated deterministic index. The correction also validates every checked-in intake record, cross-checks evaluation and provenance identities with the manifest, requires each source to have a digest-matching source-to-target mapping, validates the declared n8n response behaviour, binds catalogue directory names to manifest ID/version, and rejects symlink references whose real target escapes the package.

## Handoffs

### WP-03 Automation Architect

Candidate creation must invoke `npm run validate:automations` and `npm run catalog:check` after writing a package. It must create only a `draft` or `eval_pending` release: certification is categorically unavailable until WP-06 delivers a verifiable independent receipt implementation.

### WP-04 Control data model

`canCreateNewInstance(lifecycle)` allows only `certified` releases. Database instance/binding rules must enforce the same policy; this source validator has no database authority.

### Later runtime/evaluation work

WP-06 owns the first certification-receipt implementation. Until it delivers a verifiable independent receipt and updates this controlled gate, every source package that claims `certified` is rejected. A JSON file containing `passed: true` or copied manifest identifiers is deliberately insufficient.

## Deferred by design

- There are no converted source packages in `automations/catalog/` yet; the generated index deliberately reports zero releases.
- The evaluator does not execute real n8n workflows yet. WP-06 owns disposable n8n/mocks and production-quality evaluation receipts.
- Database lifecycle/instance enforcement, deployment, secrets delivery, and runtime binding remain outside WP-02.
